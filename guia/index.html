Multi-tenant · fila de jobs · em desenvolvimento

Um gateway só pra despachar pipelines de mídia

imkt5 é uma plataforma modular que recebe um pedido — imagem, áudio, vídeo, pesquisa de mercado, texto — e despacha pro worker certo via fila de jobs, com fallback local-first e receitas declarativas em YAML pra fluxos compostos.

Começar o guia Ver no GitHub
O que é

Roteador de trabalho pra pipelines de mídia

Cada worker (imagem, áudio, pesquisa, revisão) é um serviço HTTP independente, rodável sozinho. O Gateway despacha por capability (ex.: image.generation, audio.tts, research.market), com múltiplas instâncias distribuídas local antes de remoto. Projeto em fase de scaffold ativo — parte já funciona ponta a ponta, parte ainda está no roadmap (veja abaixo).

🧩 Recipe engine

Fluxos compostos declarados em YAML (recipes/*.yaml), com dependências, paralelismo (fanout) e 3 modos de aprovação por etapa.

🔀 Capability matcher

Registry de workers com local:true/false + prioridade + health-check periódico; cai pro próximo worker se o preferido estiver fora do ar.

🏢 Multi-tenant desde o schema

tenant_id em toda assinatura e linha de dado — sem "tenant default" escondido. Config em 3 níveis: global / tenant / usuário.

Como funciona

Canal → Gateway → Fila → Worker

Hoje a entrada é via HTTP direto (POST /jobs) ou a UI web em /ui; os canais Telegram/WhatsApp ainda estão pendentes (veja Roadmap). Dois modos de despacho:

Canais (Web hoje · TG/WA planejados)→ Gateway HTTP→ Capability matcher→ Worker(s)

Quick dispatch

Pedido simples (1 capability) — POST /jobs direto, sem receita. Ex.: gerar 1 imagem, rodar 1 pesquisa.

Recipe Runner

Fluxo composto (várias capabilities encadeadas) definido em YAML, com needs, payload_from e aprovações — ex.: recipes/campanha-marketing.yaml.

Pré-requisitos

O que precisa estar no ar

Só o Python + venv é obrigatório pra subir o gateway. Cada worker real depende de um upstream — sem ele, o worker simplesmente fica indisponível e o matcher pula pro próximo.

Python 3.11+

Ambiente do projeto.

# criar e instalar
python -m venv .venv
.venv/bin/pip install -e ".[dev]" pyyaml fakeredis httpx

Ollama local

Necessário pro worker auto-reviewer (revisão via LLM).

# baixar o modelo usado
ollama pull qwen2.5:14b
ollama serve

TAVILY_API_KEY

Opcional — precisa estar no .env pro worker research (pesquisa de mercado).

# .env
TAVILY_API_KEY=...

inemaimg (opcional)

Em localhost:8000 — necessário pra image.generation real (flux2-klein / qwen-edit / ernie).

inemavox (opcional)

Em localhost:8010 — necessário pra audio.tts / dubbing / transcribe real.

Guia de uso · passo a passo

Subir o gateway e mandar o primeiro job

Comandos reais do repo, testados via scripts/start-dev.sh.

1

Instale as dependências

Cria o venv e instala o pacote em modo editável.

python -m venv .venv
.venv/bin/pip install -e ".[dev]" pyyaml fakeredis httpx
2

Suba tudo

Sobe o gateway (porta 8080) e os workers que conseguirem responder health-check (auto-reviewer sempre; research se houver TAVILY_API_KEY; inemaimg-adapter/inemavox-adapter se os upstreams estiverem no ar).

./scripts/start-dev.sh  # logs em logs/<servico>.log
3

Abra a UI web

Interface simples pra disparar jobs sem precisar de curl.

open http://localhost:8080/ui
4

Confira o que está disponível

Lista os workers registrados (com status de health) e as capabilities que cada um oferece.

curl -s http://localhost:8080/workers | python3 -m json.tool
curl -s http://localhost:8080/capabilities | python3 -m json.tool
5

Dispare um job (quick dispatch)

Pesquisa de mercado via Tavily — não depende de nenhum serviço local.

curl -X POST http://localhost:8080/jobs \
  -H "Content-Type: application/json" \
  -d '{"capability":"research.market","payload":{"queries":["café 2026"]}}'  # -> {"job_id": "..."}
6

Acompanhe o resultado

Quick dispatch é fire-and-forget — o resultado sai no log do worker, não na resposta do POST.

tail -20 logs/research.log
7

Pare tudo

./scripts/stop-dev.sh
Exemplos

Dois jobs reais, via curl

O projeto ainda não tem front-end com galeria — estes são os payloads exatos usados no doc/QUICKSTART.md do repo.

# pesquisa de mercado (Tavily, real)
curl -s -X POST http://localhost:8080/jobs \
  -H "Content-Type: application/json" \
  -d '{
    "tenant_id": "demo",
    "user_id": "u1",
    "capability": "research.market",
    "payload": {
      "queries": ["tendências café gelado brasil 2026"],
      "max_results_per_query": 3
    }
  }'
# geração de imagem (inemaimg / flux2-klein, real)
curl -s -X POST http://localhost:8080/jobs \
  -H "Content-Type: application/json" \
  -d '{
    "tenant_id": "demo",
    "user_id": "u1",
    "capability": "image.generation",
    "payload": {
      "model": "flux2-klein",
      "prompt": "a happy capybara sipping iced coffee",
      "steps": 15,
      "width": 512,
      "height": 512
    }
  }'
