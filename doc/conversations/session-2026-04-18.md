from claude_agent_sdk import query, ClaudeAgentOptions

async def _call_claude_code(system_prompt, user_prompt, ...):
    opts = ClaudeAgentOptions(
        system_prompt=system_prompt,
        permission_mode="bypassPermissions",
        model="claude-haiku-4-5",  # ou sonnet-4-6

    async for event in query(prompt=user_prompt, options=opts):
        if event.get("type") == "result":

### O que é o S3

**S3** (Simple Storage Service, da Amazon) é um "armazenamento de arquivos na nuvem". Você joga um arquivo lá via API HTTP e ele devolve uma URL pública.

**Por que importa pro imkt4:**
- Hoje: imagens/vídeos ficam em `data/artifacts/` no disco. URL tipo `/artifacts/inema/xxx/video.mp4` só funciona pra quem está na mesma rede do gateway.
- Com S3: URL pública tipo `https://meubucket.s3.amazonaws.com/inema/xxx/video.mp4` que **Instagram/YouTube/TikTok conseguem baixar** pra fazer upload. Sem URL pública, os platform workers (Instagram etc) não funcionam — API deles exige URL acessível da internet.

**MinIO**: é um "S3 caseiro" — mesma API do S3 da Amazon, mas roda no seu servidor. Já subimos no Docker (porta 9000). Ou seja, dá pra usar localmente antes de migrar pro S3 real.

### Como funciona

- **Session per-browser** — cada aba abre uma "sessão" com UUID (igual um chat_id do Telegram). Persiste no localStorage; botão `nova` cria outra.
- **Input**: Enter envia · Shift+Enter quebra linha · textarea cresce automaticamente.

- **Histórico persistente** no localStorage — sobrevive refresh até você clicar "nova".
- **Auth** usa o mesmo token (user ou admin).

## Sobre o sync real

Hoje o karaoke **NÃO é sincronizado com a fala** — é fake:
- pego `full_narration` (texto)
- divido igualmente pelo total de duração: `per_word = total_dur / n_words`
- cada palavra recebe um slot fixo de ~0.2s

Por isso às vezes "fecha" com a fala por acaso, mas sai do ritmo quando TTS pausa, acelera ou a palavra é longa.

**Solução correta**: usar word-level timings da narração real. Opções:

| Opção | Custo | Precisão | Complexidade |
|---|---|---|---|
| **faster-whisper** local (post-TTS) | grátis, ~2s por 15s de áudio | alta (~95% word-accurate) | fácil; +dep Python |
| TTS nativo com marks (ElevenLabs) | já pago | perfeito | fácil; precisa trocar provider |
| Aeneas/Gentle forced alignment | grátis | média-alta | médio; binários externos |

**Recomendação**: `faster-whisper`. Adiciono um worker `audio.transcribe_words` ou um passo dentro do ffmpeg-local que roda whisper no áudio gerado, pega timestamps reais de palavra, substitui no ASS.

## Item 4 — `distributeSceneDurations` proporcional ao áudio

**O que é**: hoje o LLM inventa durações por cena (ex.: cena 0 = 2.5s, cena 1 = 3.5s, cena 2 = 4s). Mas quando a narração real é gerada pelo TTS, ela não respeita esses tempos — pode falar 12s de coisas pra cenas que somam 10s, ou inversamente.

No mkt3, tinha `distributeSceneDurations()` que:
1. Gera narração por cena (cada `narration` do scene_plan).
2. Mede a duração real de cada áudio.
3. Ajusta `scene.duration` baseado em (a) duração real + (b) margem de respiro.
4. Se texto é curto, dá espaço silencioso extra pra "absorver" o ponto.

Hoje no imkt4: TTS gera um áudio só (com `full_narration` concatenado). Não temos narração por cena.

**Como implementar (2 níveis)**:

**Nível básico** (ajusta duração total):
- Mede duração real do mp3 de narração.
- Se narração > soma das scene_durations → escala todas as cenas proporcionalmente pra caber narração inteira + 1s de buffer.
- Se narração < total → cena final ganha o resto como "hold".

**Nível completo (mkt3-style)**:
- Muda recipe: stage `voiceover` gera **N arquivos** (um por cena, usando `scene.narration`).
- Mede duração de cada um.
- `scene.duration` = max(scene.duration, audio_duration + 0.3s).
- Ganha sincronia por cena + permite karaoke perfeito por cena.

**Esforço**:
- Básico: S (~20min).
- Completo: M-L (~1h30, mexe na recipe também).

## Item 14 — Freeze frame + zoom em revelações

**O que é**: um recurso narrativo/visual clássico — num momento de "revelação" (dado importante, CTA forte, plot twist do conteúdo), o vídeo **congela** por 0.5-1s com um zoom rápido + SFX ding/stab, destacando o momento.

**Exemplo**:
- Cena 2 (dica principal) chega ao ponto: "a IA **triplica** a produtividade".
- No momento da palavra "triplica" → freeze frame + zoom 1.15x + SFX ding + texto realça.
- Espectador absorve o dado. 0.8s depois volta pro ritmo.

**Mercado 2025-2026**: **ainda converte**. Usado por educadores no YouTube Shorts, creators de finanças, posts de ciência. É tátil, humano, não-automatizado — parece edição premium.

**mkt3 tinha?** Não — motion era contínuo.

**Como implementar**:

**Opção A — Freeze flag por cena**:
- LLM planner marca cena com `freeze_at: 1.5` (timestamp dentro da cena onde congela) + `freeze_duration: 0.8`.
- Ffmpeg-local: quando encontra essa flag, corta o clip em 3 partes: pré-freeze, freeze (still frame com zoom), pós-freeze.
- SFX ding tocado no início do freeze.

**Opção B — Word-level trigger (precisa sync)**:
- Depende do item 1 (karaoke sync com whisper).
- LLM marca palavra-chave com `emphasis: true`. Quando essa palavra é falada (timing real), aplica freeze.
- Mais preciso mas depende de outro item já estar pronto.

**Opção C — Style-based automático**:
- Styles `data_viz`, `editorial`, `corporate_clean` ativam freeze automaticamente em cenas com `stat_a` (dado revelado).
- Sem flag explícita, sem LLM extra.

**Esforço**:
- A: M (~1h, cortar clip + reintegrar).
- B: S (~30min, depende do item 1).
- C: S (~30min, heurística simples).

**Sua decisão?**
- **A)** Per-cena flag manual + LLM sugere.
- **B)** Word-level (depende do item 1).
- **C)** Style-based auto.
- **D)** Pula.
